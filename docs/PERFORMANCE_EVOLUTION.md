# RepoMindAI Performance Evolution

Date: 2026-06-01

This document records benchmark-driven optimization passes. Benchmarks are generated by `scripts/platform_benchmark.py` and written to `reports/performance/`.

## Benchmark Protocol

Run local smoke benchmark:

```bash
.venv/bin/python scripts/platform_benchmark.py --tier tiny
```

Run real open-source scale benchmark:

```bash
.venv/bin/python scripts/platform_benchmark.py --include-network --limit 3
```

Collected metrics:
- CPU seconds
- max RSS
- ingestion time
- analysis time
- dependency graph time
- report generation time
- security scan time
- chat retrieval latency
- PR analysis latency
- drift analysis latency

## Iteration 1

Change:
- Added benchmark harness covering ingestion, analysis, graph, security, reports, retrieval, PR risk, and drift.
- Added `reports/performance/latest.json` and `latest.md` output format.

Evidence:
- Harness runs against local tiny repository without network.
- Network mode uses real open-source repositories: Flask, FastAPI, Django, Next.js, Kubernetes.

Result:
- Tiny local benchmark passed and wrote `reports/performance/latest.json`.
- Measured baseline: 6 files, 7 indexed chunks, 14.3985s analysis, 7.027s retrieval, 1621.29 MB max RSS.
- Top bottlenecks: analysis (67.2%) and retrieval/model-index path (32.8%).
- No optimization claim is made yet because this iteration established measurement rather than changing hot code paths.

Next optimization loop:
1. Warm and cache embedding/retrieval dependencies before timed retrieval measurement.
2. Run tiny/small/medium benchmarks with network mode.
3. Optimize the dominant analysis stage only after per-stage timings identify parser, embedding, scanner, or report generation as the root cause.
4. Re-run the same targets.
5. Keep change only if wall time or RSS improves materially without reducing test coverage.

## Architectural Ceiling

Expected ceiling before distributed architecture:
- Single host CPU and RAM bound for very large repositories.
- Embedded Chroma and client-side graph rendering limit graph scale.
- ThreadPool worker model limits horizontal scaling and job durability.
