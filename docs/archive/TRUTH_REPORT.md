# Truth Report

Date: 2026-05-23 UTC

## Can This Actually Be Used?

Yes, with caveats. RepoMindAI can ingest repositories, analyze code, generate local reports, build a retrieval index, answer questions with a local model, and show results through the UI/API. It was validated on FastAPI, Flask, Next.js, and RepoMindAI itself.

It is not production-grade against the original full specification. It is a working local prototype with real analysis and local model inference, plus several stubbed infrastructure pieces.

## What Is Real

- GitHub clone ingestion
- Local path ingestion
- ZIP ingestion code path
- File filtering and hashing
- Language/framework/package detection
- Python AST parsing
- JS/TS regex symbol extraction
- Dependency graph construction
- Security heuristic scanning plus Bandit support
- Radon-based Python maintainability analysis
- JSON-backed repository metadata store
- Local deterministic RAG indexing and retrieval
- Actual local qwen-judge model loading and generation
- Markdown reports
- ZIP report export
- FastAPI API
- Next.js dashboard
- Test suite

## What Is Partial

- AST parsing: Python is real; JS/TS is regex, not Tree-sitter AST.
- Dependency graph: import/symbol graph only, not true runtime call graph.
- RAG: local and cited, but embeddings are deterministic hash embeddings, not semantic transformer embeddings.
- Security: regex and Bandit, no Semgrep.
- Scoring: now evidence-based, but still heuristic.
- Reviews: generated by a real local model, but output can include reasoning preambles.
- Docker: files exist, Compose not verified.

## What Is Fake or Stubbed

- PostgreSQL runtime storage: models exist, runtime uses JSON.
- Redis/Celery background execution: task exists, API runs synchronously.
- ChromaDB runtime vector store: dependency exists, not used.
- shadcn/ui: not actually used.
- PDF export: not implemented.
- Semgrep orchestration: not implemented.
